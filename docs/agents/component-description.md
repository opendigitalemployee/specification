# Describe an agent's existing composition

**Informative application guide · 0.3.0 · 4 October 2026.** Use this after the reflective [self-description route](../../spec/research/proposals/personal-starter-slice.md). The result describes what exists and exposes follow-up questions. It is an experimental view over sources and existing concepts, not a new normative agent kind or a passing restoration assessment.

## Finish the known description

| Family | Record | Keep separate |
|---|---|---|
| Identity and instructions | Home, native files, semantic role, exact revision, current/historical status, entry order, task-specific loading and dependencies | Personal identity, current assignment, historical bootstrap and platform instructions |
| Shared basis | Selected local/shared revision, provenance and external context pointers | Reusable class context, professional DNA and optional research; one does not automatically redefine another |
| Memory | Own/inherited zones, entrypoints, selection rules, history/update lifecycle, dates and privacy | Stored bytes, loaded context and current human state |
| Methods | Available native skill entrypoints, versions, current selection, observed use and supporting-resource boundary | Installed, selected and successfully applied; file presence does not prove qualification |
| Data | Logical source/storage purpose, location/alias target, coverage, freshness, access and current task relationship | Source provenance, data-store description and a captured data snapshot |
| Runtime | Observed family/configuration, tools/connections, schedules/hooks, limits and unknowns | Advertised operations, authenticated access and current permission |
| Governance and maintenance | Assignment/review responsibility, action boundaries, stop/handoff rules, version/review triggers and disclosure | Description agreement, capability evidence, technical enforcement and current authority |

Record a known item's purpose, source/version, lifecycle, loading/use rule, dependencies, observed basis, content location, inclusion boundary and remaining question. Native files retain their meaning; their filename alone does not define the semantic role. Equal hashes establish equal observed bytes, not future canonical ownership. An index can link independently versioned profile, composition, audit and assessment artifacts without duplicating source text or introducing hash-reference cycles.

Formal works need not already exist. Describe actual current activities as observations. Do not fabricate Work contracts, acceptance criteria, outcomes, qualification or permission to complete a form. If those were not defined, record the gap for later analysis or owner discussion. The same applies to missing budgets, runtime versions and measurements.

## Stop the description at its files and explicit dependencies

The self-description result is a finite set of answer/profile/component files with an index, source versions and explicit known dependencies. The agent may synthesize explanatory files to answer the questions; their claims retain provenance and uncertainty. Native identity/instruction/memory files keep their own roles. The index inventories the description output, not an implied snapshot of every cited source.

For a dependency, describe its purpose and relationship to the agent, locator/revision, known boundary and unresolved facts. Distinguish an agent component, shared basis, environment requirement and claim evidence. The [experimental collection contract](self-description-contract.md) defines these relationships for description output; they are separate from normative ODE kinds. A workspace path never silently selects its entire tree for capture. An available native skill is distinct from a method selected by the agent and from independently demonstrated capability.

An independently scoped backup tool consumes this output and preservation context. It computes dependency closure, selects traversal depth, includes exact files or subsets, creates derived summaries where appropriate, declares outside/missing resources and packages the result. Those operations are not prerequisites for finishing the self-description. Record manual capture rules in the backup plan rather than treating them as facts about the agent.

A summary is a separate resource with its own identity/version/digest, source provenance, selection coverage and limitations. It does not inherit the original's digest or prove complete preservation. The selected backup scope decides whether that derivative is sufficient. See the [description/capture boundary](description-and-restoration.md#description-and-backup-have-separate-deliverables).

## Route the remaining questions

| Route | Suitable gap | Result |
|---|---|---|
| Source analysis | Current file/configuration, exact external target, observed artifact/evidence | Dated observation with scope; broader account or machine discovery is not implied |
| Owner conversation | Useful work/outcome, priority, standing initiative, responsibility, attention budget or preservation scope | Explicit contextual decision; do not infer it from metadata |
| Standard design | A relationship or contract the current format cannot express | Reviewable proposal, affected files and version impact; normative adoption separately recorded |

Complete an author pass when all selected component families have their known sources and limits recorded and the remaining questions are routed. This does not require all [self-diagnosis answers](self-diagnosis.md) to be filled, does not assign a mature-agent score and does not mean the owner agreed. Pin the scope and artifact hashes; keep earlier assessments unchanged and assess the new version separately.

## Fit with current ODE

Role/Work, Skill and ActivationBinding, Source/Storage/Environment, InteractionContract, Policy, native resources, exact references and backup inventory already cover important parts of the composition. Use them where their semantics fit. Normative 0.2 uses [Party affiliations](procedures/affiliation.md) without organization-only references; a class/identity basis is not automatically a professional AgentDNA. No fictitious Organization is introduced by this guide.

Keep capture and execution explicit. A path/hash inventory cannot restore missing bytes or secrets. Full selected skill directories, chosen data and target support belong to a later scoped resource-preservation step. Migration exams are a future application need in the current case; no exam tasks, criteria or runner are designed here. See [description and restoration](description-and-restoration.md).
