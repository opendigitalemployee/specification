# Propose a change

Start with the [specification](spec/SPECIFICATION.md) and [scope](STATUS.md). Describe the problem, affected objects and relationships, impact on saved packages, a concrete example, and a verification case. Changes to normative semantics require a versioned specification; changes to a released object require its own version.

Keep outcome, output, Work, Workflow, Skill and ToolDefinition distinct. Use stable glossary IDs; English is the reference language and translations are reviewed separately. Native formats retain their own rules. Include a primary source and observed revision when proposing an integration.

This candidate is exported from a curated source. External proposals are reviewed there and included in a subsequent export; do not maintain an independent hand-edited copy. Check [the license map](LICENSING.md) for the affected files. State the intended licensing of your contribution and do not submit private company or personal data.
